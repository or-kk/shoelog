# ShoeLog Android 앱 설계

## 1. 목적과 범위

ShoeLog는 갤럭시 워치와 삼성헬스가 기록한 달리기를 Android Health Connect에서 읽어 와, 각 운동에 사용한 러닝화를 배정하고 신발별 누적거리를 관리하는 휴대폰 전용 앱이다.

첫 버전은 다음 원칙을 따른다.

- 갤럭시 워치 앱, 서버, 계정, 광고, 결제, 웹 크롤링을 만들지 않는다.
- 운동 및 신발 데이터는 기기 내부에만 저장한다.
- Health Connect 데이터는 읽기만 하며 삼성헬스 원본을 수정하거나 삭제하지 않는다.
- 운동 세션과 거리 외에 위치, 경로, 심박수, 수면 데이터는 요청하지 않는다.
- 앱 실행 시 동기화와 수동 새로고침을 우선하며 백그라운드 상시 감지는 하지 않는다.

## 2. 기술 선택

- Kotlin, Gradle Kotlin DSL, Version Catalog
- Jetpack Compose, Material 3, Navigation Compose
- ViewModel, Coroutines, Flow
- Room: 신발, 운동, 배정 저장
- Preferences DataStore: 개인 설정 저장
- Health Connect Jetpack 라이브러리
- Android Photo Picker: 신발 사진 선택
- 앱 실행 중 발견한 미배정 운동 알림

프로젝트는 단일 `app` 모듈을 유지한다. 기능 규모에 비해 멀티모듈이 주는 빌드 및 의존성 관리 비용이 더 크기 때문이다. 대신 패키지 경계를 명확히 해 기능과 데이터 접근을 격리한다.

## 3. 프로젝트 구조

```text
ai.orkk.shoelog
├── data
│   ├── health       Health Connect 상태·권한·레코드 접근
│   ├── local        Room 엔티티·DAO·데이터베이스
│   ├── preferences  DataStore 설정
│   └── repository   로컬·Health Connect 데이터 조합
├── domain
│   ├── model        UI와 저장소에 독립적인 모델
│   └── usecase      마일리지·진행률·동기화 규칙
├── ui
│   ├── home
│   ├── shoes
│   ├── exercises
│   ├── settings
│   ├── navigation
│   └── theme
└── notification     알림 채널과 딥 링크
```

Health Connect 접근은 `HealthConnectDataSource` 인터페이스 뒤에 둔다. 실제 구현과 가짜 구현이 같은 계약을 사용하므로 Health Connect나 삼성헬스가 없는 환경에서도 도메인 및 ViewModel 테스트가 가능하다.

## 4. 데이터 모델

### ShoeEntity

- 내부 ID
- 브랜드, 모델명, 별칭, 색상
- 구매일, 사용 시작일
- 초기거리(meter 단위 정수)
- 목표거리(meter 단위 정수)
- Photo Picker URI 문자열
- 활성/은퇴 상태
- 기본 신발 여부
- 생성·수정 시각

### ExerciseEntity

- Health Connect 원본 레코드 ID를 사용한 고유 ID
- 보조 안정 식별값(출처, 시작·종료 시각을 정규화한 해시)
- 시작·종료 시각
- 운동 종류
- 거리(meter 단위 정수, 없으면 null)
- 데이터 출처 패키지와 표시명
- 원본 마지막 수정 시각과 앱 동기화 시각
- 원본에서 사라졌는지를 나타내는 상태

### ExerciseShoeAssignmentEntity

- 운동 ID(고유 외래키)
- 신발 ID
- 자동 배정 여부
- 배정·수정 시각

운동 하나에는 신발 하나만 배정할 수 있다. 신발을 은퇴해도 기존 배정은 유지한다. 사용 기록이 있는 신발은 삭제 대신 은퇴를 우선하며, 신발을 실제 삭제할 때도 운동은 보존하고 배정만 해제한다.

### AppSettings

DataStore에 기본 신발 자동 배정, 기본 신발 ID, 과거 기록 접근 선택, 마지막 동기화 정보, 샘플 데이터 상태를 저장한다. 이 파일은 Android 백업 대상과 Git 커밋 대상에서 제외되는 앱 런타임 데이터다.

## 5. 거리와 마일리지 규칙

내부 계산은 부동소수점 오차를 피하기 위해 meter 단위 정수로 한다. 화면에서만 km로 변환해 소수점 한 자리로 표시한다.

```text
누적거리 = 초기거리 + 유효한 배정 운동 거리 합계
사용률 = 목표거리가 0보다 클 때 누적거리 / 목표거리
남은 거리 = max(목표거리 - 누적거리, 0)
```

진행 상태는 정상, 임박, 도달로 나눈다. 기본 임박 기준은 목표거리의 90% 이상이다. 운동 배정 변경·해제, 원본 거리 수정, 원본 삭제 상태 변경은 Flow 기반 Room 쿼리에 즉시 반영된다. 누적거리 자체는 별도 컬럼으로 저장하지 않는다.

## 6. Health Connect 연결과 동기화

앱 시작 시 Health Connect SDK 상태를 `사용 가능`, `설치 또는 업데이트 필요`, `미지원`으로 구분한다. 권한 요청 전에 운동 세션과 거리 데이터가 필요한 이유를 한국어 화면으로 설명한다.

기본 권한은 달리기 운동 세션 및 거리 읽기뿐이다. 30일보다 오래된 기록 접근은 설정에서 사용자가 선택하고 기기의 Health Connect가 해당 기능을 지원할 때만 `READ_HEALTH_DATA_HISTORY` 권한을 요청한다.

동기화 순서는 다음과 같다.

1. SDK 상태와 권한을 확인한다.
2. 허용된 기간의 `ExerciseSessionRecord` 중 달리기 종류만 읽는다.
3. 각 운동의 시작·종료 시각과 동일한 데이터 출처를 필터로 사용해 `DistanceRecord.DISTANCE_TOTAL`을 집계한다. Health Connect 집계 API가 구간 경계와 출처 우선순위를 처리하게 하며 앱에서 임의 비례 계산하지 않는다.
4. 집계 결과가 없거나 0이면 운동을 `거리 정보 없음` 상태로 저장한다.
5. 원본 레코드 ID로 upsert하고, ID를 얻지 못한 경우에만 안정 식별값으로 중복을 막는다.
6. 기존 운동의 거리·시각·출처 변경을 갱신한다.
7. 동기화 범위에서 원본이 사라진 운동은 즉시 물리 삭제하지 않고 `sourceDeleted`로 표시해 배정 및 합계에서 제외한다.
8. 새 미배정 운동이 있으면 기본 신발 자동 배정 설정을 적용하고, 남은 미배정 운동에 대해 알림을 생성한다.

삼성헬스 여부는 Health Connect가 노출하는 데이터 출처 패키지로 가능한 범위에서 식별한다. 출처가 명확하지 않으면 일반 Health Connect 기록으로 표시하며 삼성헬스라고 추정하지 않는다. 삼성헬스와 Health Connect 간 동기화 지연은 별도 안내 문구로 설명한다.

## 7. 화면과 사용자 흐름

### 홈

연결·권한·동기화 상태, 새로고침, 미배정 운동 수, 최근 달리기, 활성 신발 카드를 보여준다. 신발 카드는 사진, 브랜드·모델, 누적거리, 목표거리, 진행률과 상태를 포함한다.

### 신발 목록 및 상세

활성 신발을 기본으로 보여주며 은퇴 신발 필터를 제공한다. 상세에는 기본정보, 누적·목표·남은 거리, 배정 운동 목록, 수정 및 은퇴 동작이 있다.

### 신발 추가·수정

브랜드 후보와 사용자가 이전에 입력한 브랜드·모델을 자동완성한다. 직접 입력을 항상 허용한다. Photo Picker로 이미지를 고르고 영구 URI 접근 권한을 유지한다. 거리와 날짜를 검증하고 기본 신발 지정 시 기존 기본 신발을 원자적으로 해제한다.

### 달리기 기록 및 배정

날짜, 시작시간, 거리, 출처, 배정 신발을 표시한다. 전체/미배정 필터를 제공한다. 항목을 선택하면 활성 신발 배정, 기존 배정 변경, 배정 해제가 가능하다. 거리 없는 운동은 `거리 정보 없음`으로 표시하고 마일리지 합계에서 제외한다.

### 설정

Health Connect 상태·권한, 동기화 실행, 기본 신발 자동 배정, 과거 기록 접근, 샘플 데이터, 개인정보 처리 안내를 제공한다.

### 시각 및 접근성

한국어를 기본으로 하고 검정·회색 기반에 선명한 라임 계열 포인트 컬러를 사용한다. 시스템 다크 모드를 지원한다. 로딩, 빈 화면, 오류, 권한 미허용 상태를 모두 명시적으로 구현한다. 아이콘과 사진에는 콘텐츠 설명을 제공하고 주요 터치 영역은 최소 48dp를 확보한다.

## 8. 알림

Android 13 이상에서는 알림을 실제로 보낼 시점에 알림 권한을 요청한다. 전용 알림 채널을 만들며 미배정 달리기가 새로 발견된 경우에만 알림을 보낸다. 알림을 누르면 달리기 기록 화면의 해당 운동 배정 흐름으로 이동한다. 첫 버전은 앱 실행 또는 수동 동기화 직후 알림만 지원한다.

## 9. 오류 및 개인정보 처리

Health Connect 미지원·업데이트 필요, 권한 거부, 기록 없음, 거리 없음, 동기화 실패, 사진 접근 실패, 과거 기록 권한 없음, 동기화 지연을 서로 다른 사용자 메시지와 복구 동작으로 표현한다.

앱은 `INTERNET` 권한을 선언하지 않는다. 건강 데이터 원문, 운동 시간·거리, 사진 URI를 로그에 출력하지 않는다. Android 백업 규칙에서 Room 데이터베이스, DataStore, 사진 URI 관련 앱 데이터를 제외한다.

저장소의 `.gitignore`는 다음을 명시적으로 제외한다.

- `local.properties`
- `*.jks`, `*.keystore`, `*.p12`, 서명 설정 파일
- 건강 데이터 export·fixture의 개인용 디렉터리
- 로컬 DataStore·개인 설정 파일
- IDE 사용자 설정과 빌드 산출물

샘플 데이터는 가상의 브랜드·모델·시각·거리만 포함하며 개인 기록을 포함하지 않는다.

## 10. 테스트 및 검증

단위 테스트는 최소한 다음을 검증한다.

- 초기거리와 배정 운동을 포함한 신발 누적거리
- 운동 배정 변경·해제 후 합계
- 원본 ID 및 안정 식별값을 통한 중복 방지
- 목표거리 진행률과 임박·도달 상태
- 거리 null 또는 0인 운동 처리
- 기본 신발 자동 배정 규칙
- Health Connect 가짜 구현을 사용한 동기화 성공·실패

Room DAO 테스트와 핵심 Compose 화면의 상태 기반 UI 테스트를 추가한다. 완료 전 `test`, `lint`, debug APK 빌드를 실행하고 APK 경로를 README 및 최종 보고에 기록한다. 실제 삼성헬스 데이터 흐름은 갤럭시 기기에서 별도 체크리스트로 검증한다.

## 11. 문서, 라이선스, GitHub 준비

README에는 앱 목적, 아키텍처, 기술, 빌드·실행, Health Connect와 삼성헬스 연결, 권한 사용 이유, 실제 기기 테스트, 제한사항, 구조, 향후 개선사항을 포함한다. 오픈소스 라이선스는 Apache License 2.0을 사용한다.

Git 저장소 기본 브랜치는 `main`으로 초기화한다. 민감·개인 파일 제외를 검증한 뒤 기능별 커밋을 만든다. GitHub 저장소는 `ShoeLog` 이름으로 생성할 수 있도록 준비하되, 공개 여부가 결정되기 전에는 원격 저장소를 생성하거나 push하지 않는다.

## 12. 완료 기준과 제한사항

완료 기준은 컴파일, 단위 테스트, lint, debug APK 생성, 주요 Compose 내비게이션 확인, 민감 파일 비추적 검증, README·LICENSE 작성이다.

에뮬레이터와 샘플 모드에서 전체 UI 흐름을 검증할 수 있어야 한다. 삼성헬스가 생성한 Health Connect 운동의 실제 출처·거리 조합, 장기간 기록 권한, Photo Picker URI 유지, 알림 딥 링크는 실제 갤럭시 기기에서 최종 확인이 필요하다.
