# ShoeLog 러닝화 분류·목적·관리 기능 설계

## 목표

기존 러닝화 등록 흐름을 확장해 러닝화 분류와 여러 사용 목적을 저장하고, 하단 내비게이션의 전용 관리 화면에서 모든 러닝화를 조회·정렬·수정·삭제할 수 있게 한다. 기존 앱 데이터는 Room 마이그레이션으로 보존한다.

## 범위

- 러닝화에 단일 분류와 여러 사용 목적 추가
- 등록, 수정, 상세, 목록 화면에 새 정보 표시
- 하단 내비게이션에 `러닝화` 메뉴 추가
- 활성·은퇴 러닝화 조회 및 정렬
- 기록이 없는 러닝화의 영구 삭제
- Room 데이터베이스 v2에서 v3으로 무손실 마이그레이션
- 관련 단위 테스트, Room 마이그레이션 테스트, Compose UI 테스트 추가
- 사용자 기능을 README에 반영

## 데이터 설계

### 러닝화 분류

분류는 한 러닝화에 하나만 선택한다. 저장할 때는 한국어 표시 문자열이 아니라 변경에 안전한 코드값을 사용한다. 상위 그룹은 선택한 세부 분류에서 파생하므로 별도 컬럼에 중복 저장하지 않는다.

| 상위 그룹 | 세부 분류 |
| --- | --- |
| 데일리 | 입문화, 맥스 쿠션화, 안정화, 올라운더, 경량 트레이너 |
| 슈퍼 트레이너 | 높은 플레이트, 라이트 플레이트, 카본 플레이트 |
| 레이싱 | 중거리, 장거리 |

도메인 계층에는 세부 분류용 enum과 상위 그룹용 enum을 둔다. 세부 분류 enum이 표시명과 상위 그룹을 제공한다.

### 사용 목적

사용 목적은 다음 고정 항목에서 여러 개 선택할 수 있다.

- 데일리
- 회복주
- LSD
- 템포런
- 인터벌
- 대회
- 트레드밀

목적도 안정적인 코드값으로 저장한다. 현재 버전에서는 사용자 정의 목적 입력을 제공하지 않는다.

### Room 저장 형식과 호환성

`ShoeEntity`에 다음 컬럼을 추가한다.

- `categoryCode`: nullable TEXT. 기존 러닝화와 사용자가 분류를 고르지 않은 러닝화는 null이다.
- `purposeCodes`: non-null TEXT, 기본값은 빈 문자열이다. 선택된 목적 코드를 중복 없이 일정한 순서로 직렬화한다.

Room 데이터베이스 버전을 3으로 올리고 명시적인 `MIGRATION_2_3`을 등록한다. 마이그레이션은 컬럼만 추가하며 기존 러닝화, 달리기 기록, 러닝화 배정, 가격 및 개인 설정을 삭제하거나 초기화하지 않는다.

## 애플리케이션 구조

기존 domain/data/ui 분리를 유지한다.

- 도메인 모델: `Shoe`와 `ShoeDraft`에 분류 및 목적 집합을 추가한다.
- 데이터 계층: entity 매핑과 Room 마이그레이션이 코드값의 영속화를 담당한다.
- 관리 ViewModel: 활성·은퇴 필터, 정렬 키, 정렬 방향, 삭제 결과를 하나의 UI 상태로 제공한다.
- 등록·수정 ViewModel: 분류 단일 선택과 목적 다중 선택을 draft에 반영하고 저장한다.
- Compose 화면: 관리 목록, 상세, 편집 화면은 도메인 모델만 사용하며 DB 직렬화 형식을 알지 못한다.

목적은 별도 연결 테이블 대신 러닝화 행에 코드 목록으로 저장한다. 현재 목적 목록이 작고 고정되어 있으며 목적별 복잡한 SQL 질의가 필요하지 않으므로 이 방식이 가장 단순하다. 향후 사용자 정의 목적이나 목적별 통계가 필요해지면 연결 테이블 도입을 별도 기능으로 검토한다.

## 화면 및 사용자 흐름

### 하단 내비게이션

메인 하단 메뉴를 다음 네 항목으로 구성한다.

1. 홈
2. 달리기
3. 러닝화
4. 설정

기존 러닝화 목록 route를 메인 목적지로 승격해 등록 화면을 거치지 않고 언제든 관리 화면에 접근할 수 있게 한다.

### 러닝화 관리 화면

- 화면 상단에 러닝화 등록 버튼을 항상 표시한다.
- 처음에는 활성 러닝화만 표시하며, 사용자가 은퇴 포함 보기로 전환할 수 있다.
- 각 카드에 이름, 브랜드·모델, 세부 분류, 목적 칩, 누적거리, 구매일, 구매가격을 표시한다.
- 값이 없는 선택 항목은 억지로 빈 레이블을 표시하지 않는다.
- 카드를 누르면 상세 화면으로 이동한다.
- 카드의 작업 메뉴에서 수정과 삭제를 선택할 수 있다.
- 빈 목록에서는 등록을 유도하되 등록 버튼은 계속 사용할 수 있다.

### 등록 및 수정

- 분류는 그룹별로 구성된 단일 선택 UI로 제공한다.
- 목적은 각 항목을 독립적으로 켜고 끌 수 있는 FilterChip 형태의 다중 선택 UI로 제공한다.
- 분류와 목적은 선택 사항이다. 기존 필수값 규칙은 유지한다.
- 새 러닝화는 현재 동작처럼 활성 상태로 저장한다.

### 상세

상세 화면에 분류 그룹·세부 분류와 선택된 목적 칩을 표시한다. 기존 수정 및 은퇴 기능을 유지하고 삭제 진입점도 제공한다.

## 정렬

관리 화면은 하나의 정렬 키와 오름차순·내림차순 방향을 선택한다.

- 누적거리
- 구매일
- 구매가격
- 정가
- 브랜드·모델
- 최근 수정일

최초 정렬은 최근 수정일 내림차순이다. 정렬은 관리 ViewModel에서 수행한다. 러닝화 수가 개인 단말 수준으로 작으므로 DAO 질의를 늘리지 않고 UI 상태에서 일관되게 처리한다. 모든 정렬은 안정적인 보조 키를 사용해 값이 같은 항목의 순서가 흔들리지 않게 한다. nullable 값은 정렬 방향과 관계없이 항상 마지막에 둔다.

## 삭제 정책과 오류 처리

- 삭제를 선택하면 대상 러닝화 이름이 포함된 확인창을 표시한다.
- 연결된 달리기 기록이 없는 러닝화만 영구 삭제한다.
- 하나 이상의 달리기 기록이 연결되어 있으면 삭제하지 않고, 은퇴 처리하거나 기록 배정을 먼저 해제하라는 안내를 표시한다.
- 삭제 가능 여부는 UI의 추측이 아니라 repository가 트랜잭션 경계에서 최종 확인한다.
- 삭제 성공 후 목록으로 돌아가며, 삭제 실패나 차단은 사용자 메시지로 표시한다.
- 현재 기본 러닝화를 삭제하면 DB의 기본 표시와 설정 저장소의 기본 러닝화 참조를 함께 정리한다.
- 동기화와 Health Connect 데이터는 러닝화 삭제 작업의 대상이 아니다.

## 데이터 흐름

1. DAO의 러닝화 Flow가 repository를 거쳐 관리 ViewModel에 전달된다.
2. ViewModel이 활성·은퇴 필터를 적용하고 선택된 기준으로 정렬해 화면 상태를 만든다.
3. 사용자가 등록 또는 수정하면 editor ViewModel이 `ShoeDraft`를 검증해 repository에 전달한다.
4. repository가 분류 및 목적 코드를 포함한 entity로 변환해 저장한다.
5. Room Flow 갱신으로 관리 목록, 상세, 홈의 관련 표시가 자동으로 갱신된다.
6. 삭제 시 repository가 연결된 기록 수를 확인하고 삭제 성공 또는 차단 결과를 반환한다.

## 테스트 전략

### 단위 테스트

- 모든 세부 분류가 올바른 상위 그룹과 표시명에 매핑되는지 검증
- 목적 코드 직렬화·역직렬화의 순서 안정성, 중복 제거, 빈 값 처리 검증
- 각 정렬 키와 방향, nullable 값 후순위, 동률 보조 정렬 검증
- 등록·수정 draft에 분류와 여러 목적이 보존되는지 검증
- 연결 기록 유무에 따른 삭제 결과 검증

### Room 테스트

- v2 데이터베이스에 기존 러닝화·가격·기록·배정 데이터를 만든 뒤 v3으로 마이그레이션
- 기존 데이터가 그대로 남고 새 컬럼이 null/빈 값으로 채워지는지 검증
- v3에서 분류와 여러 목적을 저장하고 다시 읽을 수 있는지 검증

### Compose UI 테스트

- 하단 러닝화 메뉴로 관리 화면 진입
- 등록·수정 화면에서 분류 단일 선택과 목적 다중 선택
- 정렬 기준 및 방향 변경 시 목록 순서
- 기록 없는 러닝화 삭제 성공
- 기록 있는 러닝화 삭제 차단 안내
- 첫 러닝화 등록 후에도 추가 등록 버튼이 계속 표시되는지 회귀 검증

연결 UI 테스트는 Android 에뮬레이터에서만 실행한다. 실제 휴대폰에서는 데이터 삭제를 유발할 수 있는 instrumentation test를 실행하지 않고, 일반 APK 설치와 수동 실행 확인만 수행한다.

## 완료 조건

- 사용자가 러닝화 등록·수정 시 분류 하나와 목적 여러 개를 저장할 수 있다.
- 하단 러닝화 메뉴에서 모든 저장된 러닝화를 조회할 수 있다.
- 요청된 모든 기준으로 정렬 방향을 바꿀 수 있다.
- 목록 또는 상세에서 수정과 안전한 삭제가 가능하다.
- 기록이 연결된 러닝화는 삭제되지 않는다.
- v2 사용자의 기존 앱 데이터가 v3 설치 후 보존된다.
- 단위 테스트, Room 마이그레이션 테스트, lint, debug 빌드, 에뮬레이터 UI 테스트가 통과한다.
- 새 debug APK를 실제 연결 휴대폰에 일반 설치 방식으로 설치할 수 있다.

## 제외 범위

- 사용자 정의 분류 또는 목적 생성
- 이미지 표에 포함된 브랜드별 모델 데이터베이스 구축
- 목적별 자동 러닝화 추천
- 여러 정렬 키를 조합하는 고급 정렬
- Health Connect 운동 기록의 자동 목적 판별
